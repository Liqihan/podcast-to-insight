这是一个非常现代且高效的技术栈组合。**Next.js** 提供了优秀的前端体验和SSR能力，**FastAPI** 完美契合AI处理逻辑，而 **Supabase** (PostgreSQL + pgvector) 则一站式解决了数据库、认证、存储和向量检索（RAG）的需求。

以下是为您细化后的 **小宇宙音频转AI总结 & 智能问答系统** 技术架构文档。

## 2. 技术栈详细说明 (Tech Stack)

| 模块 | 技术选型 | 关键说明 |

### 3.2 核心表结构

**1. Episodes (单集表)**
```sql
create table episodes (
  id bigint generated by default as identity primary key,
  xyz_id text unique not null, -- 小宇宙 ID
  title text,
  description text,
  audio_url text, -- 原始链接
  storage_path text, -- Supabase Storage 中的备份路径
  cover_image text,
  duration int,
  created_at timestamp with time zone default timezone('utc'::text, now())
);
```

**2. Summaries (总结结果表)**
```sql
create table summaries (
  id uuid default gen_random_uuid() primary key,
  episode_id bigint references episodes(id),
  user_id uuid references auth.users(id), -- 关联 Supabase Auth 用户
  status text check (status in ('pending', 'processing', 'completed', 'failed')),

  -- 摘要与结构化输出
  summary_text text,          -- 摘要正文 (Markdown/纯文本)
  one_sentence_summary text,  -- 一句话总结
  key_takeaways text[],       -- 核心观点列表
  action_items text[],        -- 行动项（可选）
  mind_map_structure jsonb,   -- 适合前端渲染思维导图的 JSON
  summary_json jsonb,         -- 结构化摘要原始 JSON（可选）

  -- 转写相关
  transcript_text_url text,   -- 纯文本逐字稿文件地址
  transcript_json_url text,   -- ASR 原始 JSON（含句/词级时间戳）
  transcript_duration_ms int, -- 转写时长（毫秒）

  language text,              -- 语言 (zh/en)
  summary_style text,         -- bullet/paragraph
  asr_model text,             -- ASR 模型
  summary_model text,         -- 总结模型

  error_message text,
  created_at timestamp with time zone default timezone('utc'::text, now())
);
```

**3. Podcast_Chunks (向量数据表 - 用于 RAG)**
这是实现“向播客提问”的核心表。我们将逐字稿切分成小块存储。
```sql
create table podcast_chunks (
  id bigint generated by default as identity primary key,
  episode_id bigint references episodes(id),
  content text,             -- 切分后的文本片段
  start_time float,         -- 该片段开始时间(秒)
  end_time float,           -- 该片段结束时间(秒)
  embedding vector(1536)    -- OpenAI text-embedding-3-small 维度
);

-- 创建索引以加速查询
create index on podcast_chunks using ivfflat (embedding vector_cosine_ops)
with (lists = 100);
```

### 4.2核心 Endpoint

#### **POST** `/api/v1/process` (提交任务)
*   **输入**: `{ "url": "https://xiaoyuzhou...", "webhook_url": "可选" }`
*   **逻辑**:
    1. 校验 URL格式和有效性。
    2. 调用 `resolve` 服务解析小宇宙链接。
    3. 写入 `episodes` 和 `summaries`表 (状态: pending)。
    4. 触发 Celery 异步任务处理完整流程。
*   **返回**: `{ "task_id": "...", "summary_id": "..." }`

#### **POST** `/api/v1/chat` (RAG 对话)
*   **输入**: `{ "episode_id": 1, "query": "主播对于AI的看法是什么？" }`
*   **逻辑**:
    1. 将 `query`转换为向量 (Embedding)。
    2. 调 Supabase RPC 函数查询 `podcast_chunks` 中最相似的 Top 5 片段。
    3. 构建 Prompt: "基于以下上下文回答用户问题..."。
    4. 调 LLM 生成回答。
*   **返回**: `{ "answer": "...", "sources": [{ "text": "...", "time": 120 }] }` (含引用时间戳)

#### **GET** `/api/v1/status/{summary_id}`
*   前端轮询或 SSE (Server-Sent Events) 获取进度。

#### **GET** `/api/v1/episode/{id}`
*   获取播客单集详细信息和总结结果。

#### **GET** `/api/v1/user/episodes`
*   获取当前用户的所有处理过的播客列表。

## 5.核心业务流程详解

### 5.1 异步 Worker 处理流程 (Python)

这是系统最复杂的部分，建议封装在 Celery Task 中。

#### 5.1.1 服务层职责划分

**resolve.py** - URL 解析服务
*   解析小宇宙链接，提取播客 ID 和元数据
*   获取真实的音频文件地址
*   验证链接有效性

**download.py** -音下载频下载服务
*   下载音频文件到本地或云存储
*   使用 `ffmpeg`转换为 16k mono mp3格
*   上传到 Supabase Storage备

**transcribe.py** - 音频转录服务
*  调用 Whisper API进行语音转文字
*   输出包含时间戳的分段文本 (segments)
*   生成完整的逐字稿 JSON 文件

**summarize.py** -内容总结服务
*   将完整文本发送给 LLM 生成结构化总结
*   输出格式：一句话摘要、核心观点、思维导图结构
*   更新数据库状态

#### 5.1.2完整处理流程

1.  **解析与下载**:
    *  调 `resolve` 服务解析小宇宙页面
    *   使用 `download` 服务获取并转换音频
    *   上传到 Supabase Storage存储
2.  **ASR转**:
    *  调用 `transcribe` 服务使用 Whisper API
    *   **关键点**: 输出格式必须包含 `segments` (含 start, end, text)
3.  **向量化 (Embedding & Indexing)**:
    *   **切片 (Chunking)**:遍历 Whisper 的 segments，将文本按语义或固定长度（如 500 tokens）合并切分。保留 `start_time`。
    *   **Embedding**: 调用 OpenAI API将切片转为向量。
    *   **存储**:批量插入 `podcast_chunks`表。
4.  **生成总结**:
    *   调用 `summarize` 服务处理完整文本
    *   Prompt要求输出 JSON 格式以便前端渲染（摘要、金句、脑图结构）
    *   更新 `summaries`表状态为 `completed`。

### 5.2 RAG (检索增强生成) 详细实现

#### 5.2.1向搜索 RPC函数

在 Supabase 中创建一个 PostgreSQL 函数，供 FastAPI调用以进行向量搜索：

``sql
create or replace function match_podcast_chunks (
  query_embedding vector(1536),
  match_threshold float,
  match_count int,
  filter_episode_id bigint
)
returns table (
  id bigint,
  content text,
  start_time float,
  similarity float
)
language plpgsql
as $$
begin
  return query
  select
    podcast_chunks.id,
    podcast_chunks.content,
    podcast_chunks.start_time,
    1 - (podcast_chunks.embedding <=> query_embedding) as similarity
  from podcast_chunks
  where podcast_chunks.episode_id = filter_episode_id
  and 1 - (podcast_chunks.embedding <=> query_embedding) > match_threshold
  order by podcast_chunks.embedding <=> query_embedding
  limit match_count;
end;
$$;
```

#### 5.2.2 RAG 查询流程

1.  **向量化查询**:将用户问题转换为向量表示
2.  **相似度检索**:调用上述 RPC函数获取最相关的文本片段
3.  **上下文构建**:组合检索到的片段作为上下文
4.  **答案生成**: 使用 LLM基上下文生成回答
5.  **引用标注**: 返回答案时包含原文片段和时间戳

4.  **Chat UI (流式输出)**:
    *   使用 Vercel AI SDK 的 `useChat` Hook
    *   Next.js API Route处理流式响应
    *   前端逐字显示 AI 的回答，提升用户体验
